# PawCare — AI Care Work Manager

> 돌봄의 맥락은 이어지고, 확인할 일은 명확해지도록.

반려견 유치원·호텔 직원의 **돌봄 기록 → 후속 업무 → 담당자 확인 → 조치 완료**를 하나의 흐름으로 연결하는 업무 관리 웹앱 프로토타입입니다. 개인 포트폴리오용이며, 모든 반려견·보호자·직원 데이터는 **가상의 샘플**입니다.

![오늘의 업무 대시보드](docs/screenshots/02-dashboard.png)

## 🚀 빠른 실행 (까먹었을 때 여기만 보세요)

**① 터미널을 열고, 프로젝트 폴더(`backend` 폴더와 `README.md`가 보이는 곳)로 이동**
```
cd 프로젝트폴더경로
```

**② 처음 한 번만: 설치 + 설정 파일 만들기** (이미 했다면 건너뛰기)
```
pip install -r requirements.txt
copy .env.example .env          ← Windows       /       cp .env.example .env   ← Mac·Linux
```
`.env` 파일에 `DEMO_MODE=1`이 있어야 로그인 없이 바로 시연할 수 있습니다. (Gemini 키는 선택 사항)

**③ 서버 켜기** — 이 터미널은 켜 둔 채로 두세요 (닫으면 서버도 꺼집니다)
```
python -m uvicorn backend.main:app --reload
```
`python`이 안 되면 `py -m uvicorn backend.main:app --reload` 로 입력하세요.
`Uvicorn running on http://127.0.0.1:8000` 이 보이면 성공입니다.

**④ 브라우저에서 열기** → **http://localhost:8000**
"선생님으로 시작하기" 또는 "보호자로 시작하기"를 누르면 로그인 없이 들어갑니다.

**⑤ 끄기** → 서버 터미널에서 `Ctrl + C`

| 이럴 땐 | 이렇게 |
|---|---|
| 페이지가 안 열려요 | ③의 서버 터미널이 켜져 있는지, 주소가 `http://localhost:8000`인지 확인 |
| `No module named backend` | 프로젝트 맨 위 폴더가 아니라 다른 폴더에서 실행한 것 → ①부터 다시 |
| `No module named ...` (그 외) | `pip install -r requirements.txt` |
| `Address already in use` | 이미 켜진 서버가 있음 → 그 터미널을 끄거나 `--port 8001`을 붙이고 `localhost:8001`로 접속 |
| 로그인 화면이 먼저 나와요 | `.env`에 `DEMO_MODE=1` 추가 후 서버 다시 켜기 (데모 계정은 아래 "시연 모드와 로그인 모드") |
| AI가 계속 "데모 분석"으로만 나와요 | 아래 **"AI 연동 → 안 될 때"** 참고. 가장 빠른 방법: `python -m backend.check_ai` (원인을 알려줍니다) |
| 코드를 새로 받았어요 | `git pull origin claude` → `pip install -r requirements.txt` → 서버 다시 켜기 |


## 이 프로토타입이 보여주려는 것

기록이 작성됐다는 사실과 *필요한 일이 실제로 처리됐다*는 사실은 다릅니다. PawCare는 이 둘을 분리해서 다룹니다.

> 가설(사용자 조사로 검증된 사실이 아님): 돌봄 정보가 메신저·구두 전달에 흩어지면, 다음 담당자가 확인했는지, 실제 조치가 끝났는지 알기 어렵다.

| 질문 | PawCare의 답 |
|---|---|
| 기록이 업무가 되려면? | 기록 저장만으로는 업무가 생기지 않습니다. 직원이 후속 업무를 **직접 승인**해야 합니다. |
| AI는 무엇을 하나? | 기록에서 후속 확인 사항을 **제안**만 합니다. 진단하지 않고, 기록에 없는 사실을 만들지 않으며, 직원이 승인하기 전에는 업무가 아닙니다. |
| 확인했다 = 끝났다? | 아닙니다. **확인 상태**(`pending` / `acknowledged`)와 **조치 상태**(`todo` / `in_progress` / `completed`)는 별개이며, 조치 완료에는 실제 조치 결과 입력이 필요합니다. |
| 보호자에게는? | 직원이 문구를 검토하고 **공개 승인**한 기록만 보입니다. 내부 메모·인계 내용은 비공개입니다. |

## 시연 흐름

아래 순서가 그대로 실제 버튼 조작으로 진행됩니다. (`tests/capture_screenshots.py`가 이 순서로 화면을 자동 캡처했습니다.)

### 1. 역할 선택 → 직원 대시보드
![역할 선택](docs/screenshots/01-role-select.png)

요약 숫자(돌봄 중, 확인 필요, 진행 중, 완료)는 DB에서 계산됩니다. 업무는 *확인 대기 → 조치 필요 → 진행 중 → 완료* 순서로 정렬되고, 완료된 업무는 일부러 덜 강조합니다. 상태는 색뿐 아니라 아이콘과 텍스트로도 표시합니다.

### 2. 반려견 프로필 · 기록 작성
| 반려견 목록 (검색·필터) | 프로필 (장기 참고사항 / 오늘 기록 / 업무) |
|---|---|
| ![반려견 목록](docs/screenshots/03-dogs.png) | ![반려견 프로필](docs/screenshots/04-dog-profile.png) |

프로필의 *지속적으로 확인해야 할 돌봄 정보*는 오늘의 기록과 구분되며, AI가 자동으로 바꾸지 않습니다.

![빠른 기록 작성](docs/screenshots/05-record-form.png)

기록 유형별 선택지로 빠르게 남깁니다. 선택한 값만으로 건강 이상을 판단하지 않습니다.

### 3. AI 후속 업무 제안 (직원이 검토·확정)
![AI 제안](docs/screenshots/06-ai-suggestion.png)

*기록에 있는 사실*과 *제안한 행동*을 나눠 보여주고, 근거 문장을 원문 그대로 인용합니다. **업무로 등록 / 수정하기 / 제안 무시** 중 직원이 고릅니다. API 키가 없으면 "데모 분석(규칙 기반 · 실제 AI 아님)"이라고 표시합니다.

### 4. 담당자 인계 → 확인 → 조치

![조치 완료](docs/screenshots/09-task-completed.png)

조치 결과를 입력해야 완료할 수 있고, 완료 시각과 변경 이력이 남습니다.

### 7. 오늘의 일과와 인계 시점
| 대시보드의 일과 구간 | 구간별 기록 현황 |
|---|---|
| ![대시보드 일과](docs/screenshots/14-dashboard-routine.png) | ![점심·휴식 구간](docs/screenshots/15-routine-lunch.png) |

유치원의 하루를 구간(등원 → 오전 교육 → 점심·휴식 → 오후 산책 → 그루밍 → 하원)으로 나누고, 기록과 업무를 그 구간에 붙입니다.
- 기록 시각에 맞춰 구간이 자동으로 정해지고(직접 바꿀 수 있음), 구간에서 바로 기록을 작성할 수 있습니다.
- **이 구간에 아직 기록이 없는 반려견**이 위에 올라와 빠뜨린 기록을 찾기 쉽습니다.
- **인계 시점**(오전 → 오후 담당자)에서는 이어받을 일(확인 대기 / 조치 필요 / 진행 중)과 그 업무 목록을 한 화면에서 처리합니다.

![인계 시점](docs/screenshots/16-routine-handoff.png)

**사진 공유 시점(M5):** 점심·휴식과 하원 준비 구간에는 "사진 공유" 표시가 붙습니다. 이 구간을 열면 사진이 공개된 아이 수, 공개 승인을 기다리는 사진이 있는 아이, 사진이 없는 아이가 나뉘어 보이고(사진이 없거나 공개 전인 아이가 위로), 공개 전 사진이 있는 아이는 곧바로 "공개 승인하러 가기"로 이어집니다.

![사진 공유 시점](docs/screenshots/30-routine-share.png)

구간 이름과 프로그램은 일반적인 예시 템플릿이며 편집 기능은 아직 없습니다. 영업시간 밖에는 오늘 가장 최근에 기록이 있는 구간을 보여줍니다.

### 8. 새 반려견 등록과 프로필 사진
| 원형 가이드로 사진 자르기 | 등록 폼 | 등록된 프로필 |
|---|---|---|
| ![사진 자르기](docs/screenshots/17-photo-cropper.png) | ![등록 폼](docs/screenshots/18-register-dog.png) | ![새 프로필](docs/screenshots/19-new-dog-profile.png) |

사진은 **어떤 비율이든 올릴 수 있고**, 브라우저에서 원형 가이드 안의 위치·확대를 맞춰 **512×512 정사각형**으로 잘라 보냅니다(드래그, 휠·슬라이더 확대, 키보드 이동 지원). 서버는 파일 형식(앞부분 시그니처까지)과 용량(1MB)을 검사하고, 올린 사진은 Git에 올라가지 않는 `uploads/`에 저장합니다.

### 9. 로그인과 보호자 초대 (M1)
| 로그인 | 직원이 만든 초대 코드(한 번만 표시) | 코드로 보호자 가입 |
|---|---|---|
| ![로그인](docs/screenshots/21-login.png) | ![초대 코드](docs/screenshots/20-invite-code.png) | ![보호자 가입](docs/screenshots/22-register.png) |

- 직원·보호자 모두 **이메일 + 비밀번호**로 로그인합니다. 비밀번호는 `scrypt` 해시로만 저장하고, 세션은 `HttpOnly` 쿠키입니다(서버에는 토큰의 해시만 저장).
- 같은 이메일로 5번 실패하면 10분간 로그인이 제한됩니다(IP별 제한도 있음). 이메일이 없는 경우와 비밀번호가 틀린 경우는 같은 메시지로 응답합니다.
- **보호자는 직원이 만든 초대 코드로만 가입**할 수 있고, 가입하면 그 반려견에 연결됩니다. 코드는 1회용·7일 만료이며, 만든 직후 한 번만 보여주고 DB에는 해시만 저장합니다. 코드 추측 시도도 횟수를 제한합니다.
- 보호자는 자기 아이의 승인된 기록만 볼 수 있고, 다른 집 아이와 직원 화면·API는 막혀 있습니다.
- 쿠키로 인증한 쓰기 요청에는 CSRF 방어용 헤더(`X-PawCare`)가 필요합니다.

### 10. 기록에 사진 첨부 (M2)
| 사진 첨부와 태그 | 프로필에서 모아 보기 | 뷰어(태그 수정·삭제) |
|---|---|---|
| ![사진 첨부](docs/screenshots/24-photo-attach.png) | ![프로필의 사진](docs/screenshots/26-dog-photos.png) | ![사진 뷰어](docs/screenshots/25-photo-viewer.png) |

- 기록을 쓸 때 사진을 **최대 10장** 첨부하고, **함께 찍힌 아이를 태그**합니다(기본은 기록의 반려견). 단체 사진은 태그된 아이들의 프로필 "오늘 찍힌 사진"에 모두 나타납니다. 기존 기록에도 "사진 추가"로 첨부할 수 있습니다.
- 브라우저에서 긴 변 1600px 이하로 줄여 올리고, 서버는 **파일을 열어 검증한 뒤 WebP로 다시 저장**합니다. 그래서 위치(GPS)·기기 정보 같은 메타데이터가 남지 않고(촬영 방향은 먼저 적용), 확장자·형식을 위조한 파일, 잘린 파일, 해상도가 거대한 파일(이미지 폭탄), 2MB 초과, 10장 초과는 거부됩니다.
- 사진은 **로그인한 같은 유치원 직원만** 인증된 경로(`/api/media/…`)로 볼 수 있습니다. 다른 유치원 직원·보호자·로그인 전에는 열 수 없고, 반려견 프로필 사진도 같은 방식으로 바꿨습니다.
 공개 승인과 보호자 알림장은 M3·M4에서 만듭니다.

### 11. 사진 공개 승인과 보호자 알림장 (M3·M4)
| 직원: 사진별 공개 대상 선택 | 보호자: 알림장(선택한 사진만) | 보호자: 사진 보기·저장 |
|---|---|---|
| ![공개 승인](docs/screenshots/27-share-modal.png) | ![보호자 알림장](docs/screenshots/28-parent-feed.png) | ![사진 보기](docs/screenshots/29-parent-viewer.png) |

- 직원은 기록을 **공개 승인**할 때 보호자에게 보여줄 문구를 쓰고, **사진마다 어느 아이의 보호자에게 보일지** 직접 고릅니다. 기본은 "이 기록의 아이"뿐이고, 함께 찍힌 다른 아이의 보호자에게 보내려면 그 칸을 직접 체크해야 합니다(체크하지 않으면 남의 집 아이가 찍힌 사진이 새지 않습니다). 사진만 공개(글 없이)도 가능합니다.
- 승인 전, 선택하지 않은 사진, 다른 집 보호자에게는 사진 주소를 알아도 열리지 않습니다(404). 공개를 취소하거나, 사진의 태그에서 아이를 빼거나, 사진을 지우면 보호자 화면에서 **즉시** 사라집니다.
- 다른 아이의 기록에 함께 찍힌 사진은 보호자 알림장에 **사진만**("친구들과 함께 찍힌 사진") 나오고, 그 기록의 글은 절대 보이지 않습니다.
- 보호자 알림장은 날짜별 피드이며 사진을 크게 보고 저장할 수 있습니다. **새 알림장 N건**은 앱 안에서만 보이는 표시입니다. 이 프로토타입에는 푸시·메시지 알림이 없고, 화면에도 그렇게 밝혀 두었습니다.
- **보호자 동의가 확인된 아이만** 공개할 수 있습니다. 반려견 등록 시 동의 확인을 체크하거나, 프로필에서 "동의 확인 기록"을 눌러야 합니다(동의서 자체는 이 앱 밖에서 받는다고 가정하고 확인 시각만 기록).

- **관리자**가 반려견을 퇴원 처리하면 새 기록·사진·업무·공개가 막히고(목록과 대시보드의 재원 수에서도 빠짐), **퇴원 3개월 뒤**로 삭제 예정일이 정해집니다. 삭제 전에는 "재등록 처리"로 되돌릴 수 있습니다.
- 삭제 예정일까지 보호자는 **이미 공개된 사진을 계속 볼 수 있고**, 보호자 화면에 삭제 예정일 안내가 나옵니다(간직할 사진은 미리 저장).
- 삭제 예정일이 지나면 그 아이의 **사진·영상 파일과 보호자 연결**이 삭제됩니다(되돌릴 수 없음). 함께 찍힌 다른 아이가 있는 단체 사진은 이 아이의 태그·공개만 지우고 **다른 아이를 위해 남깁니다.** 글로 된 돌봄 기록과 업무 이력은 그대로 남습니다.
- 삭제는 **서버가 시작될 때** 자동으로 점검하고, 관리자가 "삭제 예정 현황"에서 **삭제 대상 정리 실행**을 눌러도 됩니다. 시간이 흐르면 저절로 지워지는 예약 작업은 없으므로, 서버를 오래 켜 두기만 하면 실행되지 않습니다.

### AI 연동 (선택)

비워 두면 규칙 기반 **데모 분석**으로 동작합니다. Gemini를 쓰려면 본인 컴퓨터에서 아래 순서로 설정합니다. **`.env`는 Git에 올라가지 않으며(`.gitignore`), 키는 서버에서만 쓰이고 프런트엔드로 전달되지 않습니다.**

1. `.env` 만들기 (프로젝트 맨 위 폴더에서)
   ```bash
   cp .env.example .env          # Windows 명령 프롬프트: copy .env.example .env
   ```
2. `.env`에 키를 입력합니다. 따옴표·공백 없이 입력합니다.
   ```
   GEMINI_API_KEY=발급받은키
   GEMINI_MODEL=
   ```
3. 내 키로 쓸 수 있는 모델 이름을 확인합니다. (모델 이름은 자주 바뀌므로 목록에서 고르세요)
   ```bash
   python -m backend.list_models
   ```
   출력된 이름 중 하나(★ 표시된 flash 계열 권장)를 `GEMINI_MODEL=`에 그대로 붙여 넣습니다.
4. 서버를 (다시) 실행합니다. `.env`를 고쳤다면 반드시 껐다 켜야 합니다.
   ```bash
   python -m uvicorn backend.main:app --reload
   ```
5. 확인: `http://localhost:8000/api/health`가 `"ai_configured": true`이고, AI 제안 화면 라벨이 **"Gemini 분석 (모델명)"** 이면 성공입니다.
   "데모 분석" 라벨과 함께 안내문이 보이면 호출이 실패해 데모 분석으로 대체된 것입니다(키·모델명·네트워크 확인).

**모델 이름은 `auto`가 편합니다.** `GEMINI_MODEL=auto`로 두면 서버가 실제로 호출이 되는 모델을 골라 쓰고(1시간 기억), 쓰던 모델이 종료되면 다시 찾습니다. 직접 정하고 싶다면 `python -m backend.check_ai --find`로 지금 되는 모델을 확인하세요(목록에 있어도 호출이 안 되는 모델이 있어서, 실제로 호출해 보고 알려줍니다). 화면에서는 **AI 업무 정리 → "사용 가능한 모델 찾기"** 버튼으로도 됩니다.

**연결 확인:** `python -m backend.check_ai`를 실행하면 실제로 한 번 호출해 보고 원인을 알려줍니다(키 값은 출력하지 않음). 서버가 켜진 화면에서는 **AI 업무 정리 → "연결 테스트"** 버튼으로도 확인할 수 있습니다. 호출이 실패하면 제안 화면 상단에 **원인**이 함께 표시되고 데모 분석으로 대체됩니다.

**안 될 때** (화면·터미널에 나오는 말 → 원인)

| 보이는 말 | 원인과 해결 |
|---|---|
| `API 키가 올바르지 않습니다` | 키를 다시 복사. `.env`에서 `GEMINI_API_KEY=키` 형태로 **따옴표·공백 없이**, 프로젝트 맨 위 폴더의 `.env`인지 확인 |
| `모델 '…'을(를) 지금은 사용할 수 없습니다` (404) | **이름이 맞아도** 모델이 종료·축소되면 404가 나고, 목록(`list_models`)에는 남아 있어도 호출은 안 될 수 있습니다(예: `gemini-2.5-flash`는 2026-10-16 종료 예정으로 알려짐). **`python -m backend.check_ai --find`** 로 지금 실제로 되는 모델을 찾거나, `.env`에 **`GEMINI_MODEL=auto`** 로 적으세요 |
| `무료 사용량 한도를 넘었습니다` | 분당/일일 한도. 잠시 뒤 재시도하거나 다른 모델로 변경 |
| `키가 거부되었습니다` | 키의 제한 설정·권한 문제. Google AI Studio에서 키 상태 확인 |
| `Google에 연결하지 못했습니다` / `시간이 초과` | 인터넷·방화벽·VPN 확인 |
| `AI 제안이 원본 기록의 근거와 맞지 않아…` | 연결은 됐지만 AI가 기록에 없는 표현을 써서 안전장치가 걸러냄(오류 아님). 기록을 더 구체적으로 쓰거나 다른 모델 시도 |
| 설정을 바꿨는데 그대로예요 | `.env`를 고친 뒤에는 서버를 **껐다 다시 켜야** 합니다(`Ctrl+C` 후 재실행) |

모델 응답은 그대로 쓰지 않고 검증합니다. 원본 기록에 없는 근거 문장이 있거나 진단·투약 표현이 있는 제안은 버립니다.

## 구조

```
backend/    FastAPI + SQLite
            database.py  schemas.py  deps.py  auth.py  seed.py
            routes/      auth · invites · dogs · records · tasks · ai · routine · misc
            services/    ai_service.py (데모 분석 + Gemini + 출력 검증)
            list_models.py  내 키로 쓸 수 있는 Gemini 모델 목록 출력
frontend/   Vanilla JS(ES modules) SPA, 직접 작성한 CSS (Ivory · Sage · Forest Ink · Clay)
            assets/dogs/  샘플 반려견 프로필 사진(더미). 사진이 없거나 불러오지 못하면 이니셜 아바타로 대체
            js/cropper.js  사진 선택·원형 가이드 크롭(라이브러리 없음)
            js/auth.js     로그인·보호자 가입 화면
            js/media.js    기록 사진 첨부(리사이즈)·썸네일·뷰어
            (backend) imaging.py  사진 검증·재인코딩(Pillow)   retention.py  퇴원 후 자료 삭제
tests/      pytest(API) · e2e_scenario.py · e2e_login_mode.py(브라우저) · capture_screenshots.py
docs/       시연 화면 캡처
```

**데이터 모델:** `organizations`, `staff`, `accounts`·`sessions`·`guardian_dogs`·`invites`·`login_attempts`(인증), `dogs`(사진 경로·보호자 동의·퇴원/삭제 예정 시각 포함), `media`·`media_dogs`(첨부 사진과 태그)·`media_shares`(사진을 공개할 반려견)·`parent_reads`(새 알림장 읽음), `routine_blocks`(일과 구간), `care_records`(보호자 공개 상태·구간 포함), `tasks`(`source_record_id`로 원본 기록 연결), `task_action_logs`. 기존 DB는 시작할 때 자동으로 마이그레이션됩니다.
모든 데이터는 `org_id`(유치원)로 분리되어, 다른 유치원 직원은 접근할 수 없습니다.

**주요 API**

| | |
|---|---|
| `GET /api/dashboard` | 요약 숫자와 정렬된 업무 목록 |
| `GET/POST /api/dogs` · `GET/PATCH /api/dogs/{id}` | 목록(검색·상태 필터)·등록, 상세·프로필 수정 |
| `POST/DELETE /api/dogs/{id}/photo` | 프로필 사진 업로드(JPG·PNG·WebP, 1MB 이하)·삭제 |
| `POST /api/records/{id}/media?dog_ids=1,2` · `GET /api/records/{id}/media` | 기록에 사진 첨부(한 장씩, 2MB 이하, 기록당 10장)·목록 |
| `GET /api/media/{id}/file?size=thumb\|full` · `PATCH`(태그) · `DELETE` · `GET /api/dogs/{id}/media` | 인증된 사진 열람·태그 수정·삭제, 반려견에 태그된 사진 |
| `GET /api/routine` · `GET /api/routine/{id}` | 일과 구간과 기록 현황, 구간 상세·인계 요약 |
| `GET/POST /api/records` | 기록 조회·생성 |
| `GET/POST /api/tasks` · `GET/PATCH /api/tasks/{id}` | 업무 조회·생성·담당자/내용 변경 |
| `POST /api/tasks/{id}/actions` | `acknowledge` · `start` · `complete`(결과 필수) · `comment` |
| `POST /api/ai/suggest-tasks` | 제안 반환(저장하지 않음) |
| `POST /api/auth/login` · `logout` · `register` · `GET /api/auth/me` | 로그인·로그아웃·보호자 가입(초대 코드)·로그인 상태 |
| `POST /api/invites` · `GET /api/dogs/{id}/guardians` · `DELETE /api/invites/{id}` | 보호자 초대 코드 발급·현황·취소(직원 전용) |
| `GET /api/parent/dogs` · `/api/parent/dogs/{id}/preview` · `POST …/seen` · `GET /api/parent/media/{id}/file` | 보호자 본인 아이의 승인된 알림장·공개된 사진·새 알림장 읽음 처리(보호자 전용) |
| `PATCH /api/records/{id}/parent-approval` (`media`: 사진별 공개 대상) · `POST /api/dogs/{id}/consent` | 공개 승인·수정·취소, 보호자 동의 확인 기록 |
| `POST /api/dogs/{id}/discharge` · `/readmit` · `GET /api/retention/discharged` · `POST /api/retention/purge` | 퇴원·재등록 처리, 삭제 예정 현황, 기한이 지난 자료 삭제(관리자) |
| `GET /api/auth/demo-accounts` · `POST /api/auth/demo-login` · `POST /api/demo/reset` | **데모 모드에서만** 동작 |

인증은 세션 쿠키(브라우저) 또는 `Authorization: Bearer`(API 클라이언트)입니다. 오류는 한국어 메시지와 필드별 `errors`로 반환합니다.

- **인증은 최소 구현입니다.** 비밀번호 재설정·이메일 인증·비밀번호 변경·계정 삭제가 없고, 직원 계정을 만드는 화면도 없습니다(샘플 직원 계정만 있음). 로그인 시도 제한은 이 서버 한 대 기준이며, 사용자 단위 잠금이므로 남이 일부러 실패를 반복시켜 잠글 수 있습니다.
- **Gemini 정상 응답 경로는 이 개발 환경(키 없음)에서 실제 호출로 검증하지 못했습니다.** 응답을 흉내 낸 테스트(성공·코드블록·JSON 모드 거부·각종 오류)와, 잘못된 키로 실제 Google 서버에 요청했을 때의 오류 안내만 확인했습니다.
